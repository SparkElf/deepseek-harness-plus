# @deepseek-ai/dsh-attachment-local

[English](README.md) | 中文

这是 [`@deepseek-ai/dsh-attachment`](../attachment) 的私有本地实现。图片、受支持的文档原件以及通用解析器产物共用 `<DSH_HOME>/attachments/v1/objects/<sha256-prefix>/<sha256>` 下的一套内容寻址命名空间，并通过不透明 `sha256:` id 寻址。原始文件名始终只是引用元数据，从不参与存储路径。

每个进程都会通过把所有祖先目录项逐级同步到文件系统根目录，对某个 home 做一次持久性证明，因此绝不会把另一个进程已经创建但尚未同步的目录误认为安全边界。写入使用私有暂存目录、仅所有者可访问的文件、已同步临时文件、原子排他硬链接发布，并在返回附件引用前同步发布目录（POSIX；Windows 依赖文件系统元数据日志）。并发去重写入方会重新校验已经发布的对象，并重复持久性同步后才报告成功。

图片操作继续保留格式专用校验。`validateImage` / `saveImage` 执行编码字节、解码媒体类型、像素数量和单边尺寸策略；`readImage` 校验摘要及日志中的图片元数据。默认单边 2000px 仍低于已部署的图片密集模型请求中最严格的上限，因为一张已接纳图片可能随会话之后的每次请求发送。

通用文件使用 `saveFile` / `readFile`。本地服务为 PDF、DOCX、PPTX 和 XLSX 准入暴露独立 `documentLimits`，而通用对象原语本身只存储已经完成领域准入的字节，并不解析它们。`readFile` 校验内容寻址摘要和已记录字节长度；会话导出读取文档原件以及未来解析器读取不可变产物时也复用这条完整性路径。

`DSH_HOME` 按共享路径策略解析：显式配置、`$DSH_HOME`，最后是 `~/.dsh`。会话日志只包含持久引用和经过校验的元数据，绝不包含这个宿主路径。图片和通用文件读取都会保留可选取消语义，而不会把 abort 转换成存储失败。

## 模型体验

该包通过重启与 fork 后仍可重建的持久附件引用间接影响模型。

#### KV 缓存影响

除请求适配器最终组装的内容块外，不产生额外影响。

## 已知限制与待完成工作

- 对象会无限期保留；基于引用的垃圾回收尚未实现。
- 本地后端假定 Host 与解析附件的消费方共享同一个文件系统服务。
- 通用文档存储只负责持久性与完整性校验；正文解析和提取内容语义属于解析器消费方。
- 动态 GIF 的元数据根据逻辑屏幕进行校验；逐帧解码策略由提供方持有。
