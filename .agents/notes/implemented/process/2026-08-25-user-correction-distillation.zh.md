# Agent Note: 用户纠正沉淀

Status: implemented

[English](2026-08-25-user-correction-distillation.md) | 中文

## Problem

要求为后续工作沉淀经验时，结果可能退化为聊天承诺、当前错误的过程记录，或另一条与现有指引重复的领域规则。这些形式都不能可靠地把纠正迁移到相邻任务，重复规则还会发生漂移。

## Decision

工作方式入口将“记住”或“沉淀”纠正的请求路由到[用户纠正沉淀技能](../../../skills/dsh-distill-user-corrections/SKILL.md)。该技能提取一个触发场景、必须动作和完成证据，检查一个相邻案例，在选择落点前搜索现有指引，并在可能时加入机械反例。最终领域规则仍留在其既有的 Skill、Agent Note 或 verifier 中，而不迁入这个元工作流。

## Alternatives considered

**依赖当前对话或模型记忆。** 聊天承诺没有持久的仓库触发入口、证据或评审面。

**把每条经验直接加入 working style。** 全局清单会累积案例专用规则，占用根指令预算，并绕过领域所有权。

**每次纠正都创建新的领域 Skill。** 触发范围重叠的 Skill 会形成多个权威位置，使后续调用更不可预测。

## Consequences

后续纠正请求拥有一个持久的学习流程，领域事实仍保持单一所有者。每次沉淀会增加一次搜索和相邻案例检查，语义质量也无法完全自动化；元数据、链接、文档门禁和聚焦反例提供可获得的机械证据。
