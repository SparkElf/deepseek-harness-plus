# Agent Note: 安全的子代理默认值与统一设置

Status: implemented

[English](2026-08-26-safe-subagent-defaults-and-unified-settings.md) | 中文

## 问题

Web 产品通过同一个工具插件挂载连续和一次性委派，却在通用插件设置中把它们显示成互不相关的卡片。两个入口默认都对模型可见，委派深度默认值三还允许子代理在用户未明确选择时继续创建后代。通用插件位置既没有表达它们属于同一能力，也没有表达启用该能力的成本。

## 决策

由 Host 持有的 `subagent` 与 `subagent-fork` settings 命名空间默认解析为 `enabled: false` 和 `maxDepth: 0`。Agent 作用域的 `dsh-tool-subagent` 实例监听自身命名空间的提交，并立即注册或移除面向模型的工具；关闭的入口既不贡献 schema，也不贡献可继续模式的提示词指引。直接组装工具插件时仍默认启用，因为加载该插件实例本身就是组合选择。

Web 客户端拥有一个独立的**子代理**导航分区。一张卡片提供连续与一次性两个标签，每个标签只编辑自己已有的命名空间。启用开关与子代理默认值因此位于同一个产品位置，同时不会合并 spawn/可继续模式与 fork/一次性模式的值。通用“插件配置”标签页不再认领这两个命名空间。

本决策部分取代[角色、工具过滤与委派深度](../feature/2026-07-12-subagent-persona-tool-filter-and-depth.md)中的三层 loader 默认值，以及[实时 Web 子代理设置](../feature/2026-08-16-web-subagent-settings.md)中的双卡片展示。两份记录中的提供方能力、命名空间生命周期和子代理请求决策仍然有效。

## 曾考虑的替代方案

**把两个模式合并到一个 settings 命名空间。** 两个模式采用不同的上下文初始化与继续执行策略。共享模型、角色、工具范围和深度值会让编辑一种模式时静默改变另一种模式。

**禁用 Loader 行。** 被禁用的 Agent preset 行无法响应用户设置，而 Host 生命周期 owner 必须保持挂载，页面才能读取和写入默认值。保留这些行并由设置控制工具注册，保存的开关才能实时生效。

**保留三代默认值。** 三是一个仍支持深度拆解的较小有限上限，但它会在用户选择之前就允许孙代理。嵌套层数零仍可使用直接委派，并把每一层更深的后代改为显式选择。

**让关闭的工具继续对模型可见并在调用时拒绝。** 这种做法仍会消耗工具 schema token，并诱导模型调用必然被策略拒绝的入口。工具注册改为遵循启用设置。

## 后果

全新部署和没有显式 `enabled` 字段的既有 settings 文档都会把两个已发布委派模式解析为关闭。启用一个模式不会启用另一个，恢复某个模式的默认值会回到关闭且不允许孙代理。settings 提交会影响当前 Agent 的工具注册表与之后创建的子代理，不改变已经创建的子代理。

独立分区增加一个设置导航项，并在用户切换标签时按模式保留未保存草稿。系统测试从 Web 设置对话框进入，验证两个默认开关和深度值、模式草稿彼此独立，并在重新打开对话框后确认已保存的开关。
