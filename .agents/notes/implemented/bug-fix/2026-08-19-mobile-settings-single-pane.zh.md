# Agent Note：移动端设置使用列表到详情面板

Status: implemented

[English](2026-08-19-mobile-settings-single-pane.md) | 中文

## Problem

设置对话框在 800px 桌面面板内保留 188px 导航栏。进入手机视口后，面板缩到视口宽度减 48px，导航栏仍保持桌面宽度，所有分区只剩约 150px。标签逐字换行，控件与说明重叠，带内缩的圆角面板还占用了额外空间，却没有改善导航。

设置包含的分区数量超过了稳定横向标签栏的容量。在手机上同时展示完整导航和一份可用表单不是有效布局。

## Decision

设置浮层 portal 到 document.body，Sidebar 的 containing block 无法再让所谓全屏面板产生内缩。视口宽度不超过 640px 时，设置填满动态视口，不绘制卡片边缘或阴影，并且每次只呈现一项任务。打开对话框先显示完整分区列表；选择一行后，列表替换为全宽分区详情。详情标题栏包含返回控件、当前分区标签和始终可用的关闭控件。分区正文负责纵向滚动，且不能撑宽页面。

既有本地活动分区 id 同时负责列表到详情导航。id 未定义时，移动端显示列表，桌面端仍派生并渲染第一个分区。首次使用引导提供分区 id 时直接进入详情。不增加视口 store、resize 订阅、重复路由或移动端专用分区实现。

桌面端保留固定导航栏和内容列。断点只改变呈现和导航深度，不改变分区注册、设置数据或插件所有权。

## Alternatives considered

- **把导航堆在活动分区上方。** 分区列表会占据手机大部分屏幕，让每次设置操作都从一长列无关菜单下方开始。
- **使用横向滚动标签栏。** 七个以上独立注册分区会隐藏在屏幕外，用户必须先发现横向滚动才能导航。
- **保留双栏并缩小字号或图标。** 内容宽度不足是结构问题；更小的文字仍然拥挤，还会降低触控和阅读质量。

## Consequences

移动端对话框具有可预测的列表和详情两层导航，同时每项功能继续注册同一个 settings.section 条目。关闭按钮在两个视图中都可聚焦，返回控件由设置标题命名，详情中保持显示当前分区标签。桌面行为和插件分区 API 不变。

## Testing

项目 Mobile Bridge Playwright 命令通过已部署中继配对一台 Pixel 7，打开真实 Harness 设置对话框，验证全视口导航不存在横向溢出，进入「通用设置」并验证标签在全宽内容区保持横排，再返回分区列表，同时检查浏览器控制台和网络健康状态。
