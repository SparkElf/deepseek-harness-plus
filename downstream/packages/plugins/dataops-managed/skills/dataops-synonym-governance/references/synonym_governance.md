# 同义词治理策略

## 一、边界

平台里三类“词”各管一件事：

| | 指标 `metrics` | 术语 `glossary_terms` | 同义词组 `synonym_groups` |
| --- | --- | --- | --- |
| 管什么 | 能算出数的指标 | 剔除指标后的业务黑话与字段含义 | 同一个词的不同写法 |
| 判定 | 有 SQL 片段，能算出数 | 有业务含义但算不出数 | 只是写法不同 |
| 例子 | GMV、月活、客户数 | 白名单、在途、贴源、宽表 | 酒店 / 旅馆 / 宾馆 / hotel |

**能不能算出一个数**：能 → 指标；不能 → 术语；只是换个写法 → 同义词组。

## 二、录入策略：自底向上

目录树就是分块器，不要另做聚类。

1. 从最底层目录开始，逐个节点读直接挂的资源卡片：名称、别名、字段中文名、描述、标签。
2. 对每个节点抽两类词：
   - `fit`：能把这个资源归到当前目录的词（目录语义词）；
   - `off`：不贴合当前目录、但能准确描述这个资源的词（资源特有词）。
3. 父节点只处理自己直接挂的资源；子节点词袋挂到 `children` 下，不重复抽取。
4. 到顶层后得到一份分层词袋，通读它找跨层关系：同一个概念在一层是 `fit`、在另一层是 `off`，通常就是同义词入口。
5. 每个候选组要能回答：它出现在哪些卡片、哪些字段、为什么判断等价。

每个节点每类词设上限（建议 `fit` 20、`off` 30），按“出现次数 × 层内稀有度”排序；超出的截断。

## 三、判定标准

- **等价**：替换后句子意思不变，且指同一个东西。酒店 / 旅馆 / 宾馆 / hotel 是等价；酒店 / 民宿 不是（民宿是另一类）。
- **上位 / 相关**：住宿 / 酒店、酒店 / 发票——不収，不要放进同一组。
- **缩写 / 中英**：可以进同一组（GMV 除外，GMV 是指标）；只保留确实在业务里互换使用的写法。
- **单字**：不单独成组，也不作为别名；单字区分度太低。

## 四、治理策略

- **标准词**：选业务里最常用的正式叫法；同一组只有一个。
- **别名**：只放确实会被用来搜索的写法；同义词组不是词典。
- **目录归属**：挂到它主要服务的业务域节点；拿不准就留空，不要硬塞。
- **启停**：不用删除，先停用；停用后不参与任何展开。
- **冲突**：一个别名只能属于一组；两组都想用时，先合并或拆清语义，不要重复录入。
- **上限**：每组 ≤ 12 个别名；超了先拆组。

## 五、优化闭环

1. **零结果查询**：搜不到的说法，先判断是资源缺失、元数据缺失，还是同义词缺口；只有最后一类才补组。
2. **用户改写**：同一会话里用户把 A 换成 B 再搜，记下来作为候选；确认等价后再入库。
3. **资源变更**：新增资源后重跑所在节点的抽词，看是否带出新写法。
4. **定期复核**：每季度看一遍组数、别名分布和停用组；过泛的拆，长期没人用的别名删。

## 六、写入后的影响

- 新建组：触发全量重建，之后所有文档按新组展开。
- 改组 / 停用：只重建展开过该组的文档，其他文档不动。
- 展开规则：文档文本里出现任一别名（归一化后子串匹配），就把整组别名补进它的检索文本；只展开一层。
