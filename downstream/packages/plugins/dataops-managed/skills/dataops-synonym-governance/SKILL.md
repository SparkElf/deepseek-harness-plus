# 同义词治理

## 适用范围

超管需要：

- 从资源卡片和数据目录里发现同义词（酒店 / 旅馆 / 宾馆 / hotel）；
- 新建、修改、停用同义词组；
- 排查“某个说法搜不到”的问题。

不适用：指标口径（`metrics`）、术语（`glossary_terms`）、资源本身的新增与迁移。

## 硬规则

1. **只走 `synonym_group_*` 工具**：禁止 shell、SQL、Prisma 或任何直写数据库的方式。
2. **写前必须让用户确认**：`create` / `update` / `delete` 都会触发审批；先把标准词、别名、依据讲清楚。
3. **一个别名只能属于一组**：冲突时先决定归属，不要硬塞；工具会拒绝。
4. **只收等价写法**：同一个东西的另一种叫法才算；上位、相关、常一起出现都不算。
5. **每组最多 12 个别名**：超过说明这组太泛，应该拆，而不是继续加。

## 流程

1. 读 `references/synonym_governance.md` 的录入策略，确认这次的目录范围。
2. 自底向上遍历目录树：每个节点抽 `fit`（贴合目录的词）和 `off`（不贴合目录但准确描述资源的词），记录出处。
3. 把候选组、别名和证据展示给用户，逐组确认。
4. 调 `synonym_group_create` 新建，或 `synonym_group_update` 补别名、改目录、启停。
5. 写入后回读并汇报；新建会触发全量重建，改组/停用只重建展开过它的文档。
