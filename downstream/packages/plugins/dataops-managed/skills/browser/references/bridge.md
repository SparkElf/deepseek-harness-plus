# 浏览器桥接 Companion

用户说「打开这个网页」「登录内网系统」「帮我点一下」「填这个表」「截个图」并涉及**用户本地浏览器**时，按本技能执行。

## 触发

- 需要用户已登录的内网系统；
- 需要用户扫码、短信验证码、MFA；
- 需要看到真实浏览器窗口并人工接管；
- 需要把网页操作结果交给 AI 继续处理。

## 连接探测（每次浏览器任务开始前）

1. 先调用 `browser_bridge_status`：
   - 返回「已连接」→ 直接进入标准流程；
   - 返回「未建立会话」「离线」「未配对」→ 进入第 2 步。
2. 调用 `browser_bridge_connect`，它会请求工作区主动建立桥接会话并等待几秒：
   - 返回「已连接」→ 进入标准流程；
   - 返回「未配对」→ 告诉用户：打开门户「账号菜单 → 浏览器桥接」页面，点「配对这台电脑」；如果本机还没装 Companion，先运行 Windows 离线安装包；
   - 返回「Companion 未在线」→ 告诉用户：在 Windows 托盘里启动「万相浏览器桥接」，确认托盘显示「已连接」，然后让你重试。
3. **不要向用户索取 8 位配对码**。一键配对由门户把配对码直接交给本机 Companion，用户只需要点按钮；配对码是内部一次性凭据，不是给用户抄写的。
4. 探测/连接失败时，明确告诉用户下一步，不要编造页面内容，也不要退化成用 curl 抓页面冒充浏览器操作。

## 标准流程

1. 用 `browser_navigate` 打开目标地址。
2. 用 `browser_snapshot` 读取页面结构，再决定点击/输入，不要盲点坐标。
3. 需要登录、验证码、MFA 时，暂停自动化：
   - 让用户在当前浏览器窗口完成；
   - 不要向用户索取密码、验证码、配对码或 Cookie；
   - 用户确认登录完成后再继续。
4. 操作完成后用 `browser_take_screenshot` 或页面文本回传结果。
5. 任务结束后释放会话，不要长期占用浏览器。

## 安全边界

- 只操作用户明确授权的域名；不访问未授权站点。
- 不读取、不导出、不上传 Cookie、LocalStorage、密码。
- 不绕过验证码、风控或登录保护。
- 涉及支付、审批、删除等高风险动作，必须先让用户确认。
- 用户要求停止/接管时，立即暂停自动化。

## 常见错误

- **`browser_*` 工具不存在**：连接器可能未启用或 Companion 未连接。先 `browser_bridge_status` → `browser_bridge_connect`；仍不行再让用户检查门户「浏览器桥接」页面和 Windows 托盘，不要猜端口。
- **连接器显示未配对**：让用户在门户「浏览器桥接」页面点「配对这台电脑」；不要手工输入配对码。
- **连接器显示离线**：让用户启动 Windows 托盘里的「万相浏览器桥接」；插件每 30 秒自动探测，托盘恢复后无需重启工作区。
- **设备已撤销**：在门户重新点「配对这台电脑」；旧设备需要重新授权。
- **浏览器没打开**：Companion 只在第一次工具调用时启动 Chromium；先调用一次 `browser_navigate`。
- **登录态丢失**：使用 Companion 的专用 profile，不要清空安装目录下的 `profile/`。
- **不要用本机 8931 端口判断生产连通性**：生产链路只认 DataOps 会话和 Companion 在线状态；本地 MCP 只监听 `127.0.0.1`。
