# Memory

个人记忆只有一套写入链路：普通会话留下消息和工具轨迹，**记忆守护会话**是唯一写入者；抽取与 SOP 评估子代理只产出带证据的判断，不直接写记忆。三条角色准则放在 `references/`，按当前角色只读一份，不要一次全读。

## 什么时候用

- 当前会话是记忆守护会话，收到 idle / compaction / dream 消息；
- 被派为记忆抽取子代理，要从会话轨迹里提长期候选；
- 被派为 SOP 评估子代理，要判断活跃 SOP 是否被使用、是否有效、下一步怎么办；
- 用户问记忆规则、隐私分级、SOP 晋升标准，或要求整理/遗忘某条记忆。

守护会话派子代理时，明确告诉它读哪份参考；子代理不要把详细报告当成交付，只回一段结论，详细证据留在临时报告里由守护会话读取后删除。

## 通用硬规则

- **只留会改变下次行为的内容**：偏好、踩坑、情景、事实、SOP 五类；闲聊、一次性查询、公共制度不进入个人记忆。
- **每条都要有证据**：能定位到原消息或工具结果；没有证据的候选不提。
- **不保存秘密**：密钥、Token、密码只记“哪份凭据、什么用途、用于哪个系统”，实际值归凭据管理器。
- **隐私分级**：`normal` / `private` / `sensitive` / `secret`；拿不准按 `private` 处理。`private` 与 `sensitive` 不进部门提炼、不进共享摘要、不导出。
- **部门 canonical 与红线优先**：个人记忆与部门制度冲突时标记冲突，不要悄悄覆盖。
- **串行处理**：守护会话按消息到达顺序一轮一轮处理；上一轮没收尾，不开始下一轮。一个用户只有一个守护会话。
- **不做机械计数**：SOP 评估靠轨迹与原文证据做整体判断，不数使用次数、不设评分阈值。
- **删除是真遗忘**：用户要求删除、偏好过期或长期低价值时，真正删除并写清原因；删除不是隐藏。

## 标准一轮（守护会话）

1. 确定今天真正活跃的会话范围（上次 dream 之后有新增消息或工具事件）；
2. 并行派抽取子代理和 SOP 评估子代理，各自按对应参考工作；
3. 合并五类记忆，去重、纠偏、遗忘，更新日文档与当前有效快照；
4. 评估并晋升 SOP：有效且可复用才沉淀为技能，技能写成功后再删除 SOP；
5. 写审计，并用个人 scope 的 Git 提交作为 dream 前后恢复点。

细节（读什么、怎么合并、怎么写标题、隐私边界、Git 恢复点命令）见 [references/guardian.md](references/guardian.md)。
