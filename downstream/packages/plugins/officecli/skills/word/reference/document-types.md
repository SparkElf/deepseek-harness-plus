# 中文法定文种内容模板（15 种）

本文件是 `word` 技能的内容模板库。**文种决定正文结构，版式包决定页面外观**；两者分开选择，不要为每个文种新建技能。

## 1. 选择顺序

1. 先定文种（下表 15 选 1；经营分析/数据分析/工作总结/调研/方案/讲话是内容 profile，挂到宿主文种，不单列文种）。
2. 再定版式包：
   - 明确“红头 / 发文机关标志 / 发文字号 / 红线” → `red-header`（任何文种都可套）；
   - 否则明确“函 / 复函 / 商洽函 / 询问函 / 答复函” → `gbt9704-letter`；
   - 否则明确“纪要 / 会议纪要” → `gbt9704-minutes`；
   - 其余（含不确定）→ `gbt9704-2012`；**不确定不升级红头**。
3. 调用 `officecli-create`（`file` + `style_pack`），再用 `officecli` 填内容。

## 3. 各文种正文骨架

### 3.1 决议

```text
标题（Title）
（可选）会议名称、通过日期（居中，JiYaoDate 或 Normal 居中）
正文：
  一、决议事项的背景与依据
  二、决议内容（分条列出）
  三、执行要求
落款（LuoKuan）：会议名称或发文机关
成文日期（ChengWenRiQi）
```

### 3.2 决定

```text
标题（Title）
主送机关（ZhuSong）：×××：
正文：
  一、决定的事由
  二、决定事项（奖励/处分/部署/变更，分条）
  三、执行要求
落款（LuoKuan）+ 成文日期（ChengWenRiQi）
```

### 3.3 命令（令）

```text
标题（Title）：××人民政府令 第×号（或“关于……的命令”）
正文：
  一、发布依据
  二、命令事项（公布/施行/授予/嘉奖）
  三、施行日期或执行要求
署名（LuoKuan）：××人民政府×××（首长）
成文日期（ChengWenRiQi）
```

### 3.4 公报

```text
标题（Title）：××公报

  一、公布事项
  二、主要内容（决定/数据/名单）
```

## 4. 内容 profile（不是文种，不单独建技能）

| Profile | 宿主文种 | 版式包 | 建议结构 |
|---|---|---|---|
| 经营分析报告 | 报告 | gbt9704-2012 | 一、总体经营情况；二、收入/成本/利润/现金流分项；三、问题与风险；四、下一步措施 |
| 数据分析报告 | 报告 | gbt9704-2012 | 一、分析背景与口径；二、数据概览；三、主要发现；四、原因分析；五、建议 |
| 工作总结 | 报告 | gbt9704-2012 | 一、主要工作与成效；二、存在问题；三、下一步安排 |
| 调研报告 | 报告 | gbt9704-2012 | 一、调研背景与方法；二、现状与问题；三、原因分析；四、对策建议 |
| 工作方案 | 意见 | gbt9704-2012 | 一、总体要求；二、主要任务；三、实施步骤；四、保障措施 |
| 讲话稿 | 意见 | gbt9704-2012 | 一、形势与认识；二、重点任务；三、工作要求 |

Profile 只改变**正文结构与内容侧重**，不改变文种、版式包和 GB/T 9704 字体字号。用户说“写一份经营分析报告”时：文种选“报告”，版式包用默认 `gbt9704-2012`，按本表“经营分析报告”的结构写。

## 5. 禁止

- 不为 15 个文种各建一个 DSH 技能；技能中心只有一个 `word`。
- 不把“经营分析报告 / 数据分析报告 / 工作总结 / 调研 / 方案 / 讲话”当成独立文种或独立技能。
- 不在正文里用空格、空行、制表符模拟缩进、居中、右对齐或表格。
- 不用 `python-docx`、`docx-creator`、`office-docx`、`office` 等通用技能补版式。
- 不把 `red-header` 当默认；不确定时用 `gbt9704-2012`。
